# Magic Phone — Web-first / Local Audio Agent

هدف: پنل وب فارسی برای تنظیم اتصال صوتی دوطرفه برنامه‌های ویندوز، با پردازش محلی و نصب استاندارد در آینده.

## فاز اول: 0.1.0 (Development Preview)

- `app/web/index.html`: رابط RTL، دو تم، انتخاب دو برنامه متفاوت و ذخیره محلی پروفایل، نمایش دستگاه‌های مجاز مرورگر و وضعیت Agent. نام برنامه‌ها گزینه‌های نمونه‌اند، نه تشخیص پردازش‌های ویندوز.
- `app/main.go`: خدمت کوچک Go فقط روی 127.0.0.1:18764، با پنل تعبیه‌شده و API فقط‌خواندنی. بدون وابستگی خارجی، بدون راه‌اندازی خودکار، بدون دانلود یا نصب درایور، بدون ضبط یا مسیریابی صدا.
- `app/main_test.go`: تست‌های HTTP و کنترل دسترسی.

## توسعه محلی (فقط توسعه‌دهنده)

در پوشه app، با Go 1.23 یا جدیدتر، `go test ./...` و `go run .` قابل اجرا هستند. پنل در http://127.0.0.1:18764/ در دسترس است. این روش نصاب کاربر نهایی نیست.

## نسخه فعلی: 0.2.0 — Windows Audio Discovery

- دکمه «شناسایی ویندوز» به صورت دستی `/api/discovery` را فراخوانی می‌کند. این API فقط روی Loopback و با همان محدودیت‌های Host/Origin و منع درخواست cross-site/same-site خارجی کار می‌کند؛ درخواست هم‌زمان دوم 429 دریافت می‌کند.
- Windows x64: شناسایی دستگاه‌های فعال ورودی و خروجی، نام و شناسه endpoint با MMDevice/IPropertyStore و جلسات صوتی قابل مشاهده با IAudioSessionManager2 و IAudioSessionControl2. نام پردازش از نام فایل اجرایی به‌دست می‌آید، نه مسیر کامل. هیچ استریم صوتی باز نمی‌شود و هیچ تنظیمی تغییر نمی‌کند.
- Windows ARM64 و سایر سیستم‌عامل‌ها فعلاً پاسخ unsupported_platform دارند. داده‌ها فقط در حافظه و پنل محلی نمایش داده می‌شوند؛ هیچ اسکن خودکار یا ارسال داده به سرور وجود ندارد.
- فهرست جلسات یک Snapshot است و ممکن است ناقص باشد؛ برنامه‌ای که هنوز جلسه صوتی ندارد ممکن است دیده نشود. برای جلسه چندپردازشی PID اولیه گزارش می‌شود. عدم مشاهده برنامه به معنی پشتیبانی نشدن آن نیست. گزینه‌های پروفایل همچنان نمونه‌اند و اتصال غیرفعال است.
- اعتبارسنجی: `go test -race -v ./...` موفق (۷ سناریوی قبلی و تست‌های جدید API شامل ۶ حالت دسترسی، عدم پشتیبانی و درخواست هم‌زمان)، `node web/discovery.test.cjs` موفق (DOM شبیه‌سازی‌شده، شناسایی صریح، نمایش متن به‌صورت امن، نتیجه ناقص، عدم پشتیبانی و خطای شبکه)، `GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build` و `GOOS=windows GOARCH=amd64 go vet ./...` موفق. اجرای واقعی COM روی ویندوز و تست زنده مرورگر انجام نشده‌اند.
- پیش از فعال‌سازی Routing: تست Windows واقعی با چند دستگاه و چند برنامه، اعتبارسنجی منابع COM، زمان پاسخ و بازیابی خطا، سپس بررسی مستندات WASAPI و درایور معتبر و مجاز. نصب‌کننده یا فایل اجرایی برای کاربر نهایی منتشر نشده است.

## معماری آینده

1. پنل HTTPS روی phone.magics.site، با اتصال به Magic Core پس از بررسی قراردادهای آن.
2. Local Audio Agent: شناسایی endpoint و جلسات صوتی اضافه شده و هنوز نیازمند تست واقعی Windows است؛ سپس مسیریابی با WASAPI پس از تأیید فاز شناسایی.
3. بررسی مجوز و درایور صوتی معتبر برای اتصال به ورودی برنامه دیگر. پشتیبانی واقعی از هر برنامه باید جداگانه آزمایش شود.
4. ارتباط وب عمومی با Agent فقط پس از طراحی Pairing، اعتبارسنجی Origin/Host، مجوز صریح کاربر، حفاظت از replay/CSRF و کنترل دسترسی Local Network Access مرورگر. نسخه کنونی عمداً CORS را باز نمی‌کند و ارتباط از مبدأ عمومی ندارد.
5. شروع یا پایان مسیر فقط با انتخاب و رضایت صریح کاربر، نمایش همیشگی فعالیت انتقال، بدون ذخیره یا ارسال مکالمات به سرور. نصب‌کننده استاندارد و بررسی امضا و مجوز درایور پیش از انتشار.

## اعتبارسنجی این مرحله

- ۷ سناریوی Go HTTP موفق: status، page، Host غیرمجاز، Origin غیرمجاز، cross-site، POST و مسیر ناشناخته.
- اجرای JavaScript در DOM شبیه‌سازی‌شده: پروفایل، منع انتخاب تکراری، ذخیره، تم، فهرست شبیه‌سازی‌شده دستگاه‌ها و وضعیت موفق/ناموفق Agent.
- ساخت Go برای Linux و کامپایل متقاطع Windows x64 موفق؛ اجرای واقعی Windows، تست درایور، و تست اتصال صوتی دوطرفه انجام نشده است.
- تست زنده Chromium روی localhost با محدودیت محیط اجرا مسدود شد؛ تأیید UI زنده نداریم.
