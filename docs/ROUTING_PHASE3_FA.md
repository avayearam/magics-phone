# Magic Phone v0.3.0 — آزمایشگاه مسیریابی صوتی بومی ویندوز

تاریخ: 2026-11-18

## تصمیم محصول

- اتصال به **Magic Core** در این فاز خارج از محدوده است. نه API مصرف می‌شود و نه پیکربندی Core اضافه می‌شود.
- رابط وب روی Loopback، موتور صوتی بومی در همان Windows Agent. هیچ صدا یا داده جلسات صوتی به سرور خارجی ارسال نمی‌شود.
- این نسخه **آزمایشی** است؛ نصاب نهایی و تضمین کیفیت صوتی ندارد.

## پیاده‌سازی

- دو جایگاه مستقل A و B در Backend با وضعیت شروع، فعال، توقف و خطا.
- دو نوع منبع: (۱) ورودی فیزیکی/مجازی صوت، (۲) Loopback کل ترکیب صوتی یک خروجی ویندوز.
- مقصد: خروجی متفاوت؛ شروع و توقف فقط با درخواست صریح کاربر.
- استفاده از WASAPI Shared Mode، IAudioCaptureClient و IAudioRenderClient بدون تغییر تنظیم پیش‌فرض صوت ویندوز.
- در این نسخه فرمت PCM ورودی و مقصد باید **دقیقاً یکسان** باشد؛ اگر نباشد، با `audio_format_mismatch_requires_resampling` متوقف می‌شود.
- صف صوتی حداکثر ۲۰۰ میلی‌ثانیه؛ در اضافه‌بار قدیمی‌ترین نمونه‌ها حذف می‌شوند. بازنمونه‌برداری و اصلاح drift هنوز اضافه نشده‌اند.
- جلوگیری از مقصدهای تکراری و مسیرهای برگشتی A⇄B که از Loopback استفاده می‌کنند؛ این بررسی جایگزین آزمایش فیدبک عملی نیست.
- API شروع/توقف با توکن تصادفی نشست محلی، تطبیق Host، Origin و Sec-Fetch-Site، نوع داده JSON و تأیید مستقیم کاربر.
- کل موتور انتقال به طور پیش‌فرض **غیرفعال** است. فعال‌سازی آزمایشی فقط با متغیر محیطی `MAGIC_PHONE_EXPERIMENTAL_AUDIO=1` هنگام اجرای Agent توسط توسعه‌دهنده امکان دارد. هیچ کلید خودکاری یا استارت پس‌زمینه‌ای تعبیه نشده است.

## محدودیت بسیار مهم

Loopback ساده WASAPI **صدای کل خروجی دستگاه** را ضبط می‌کند؛ به معنای جداکردن صدای یک نرم‌افزار مشخص مثل Chrome، Telegram یا Phone Link نیست. برای جداکردن صدای برنامه‌های مستقل، مسیر Application Loopback Capture بر اساس شناسه فرایند (و آزمون نسخه ویندوز) باید جداگانه پیاده‌سازی و بررسی شود. همچنین انتقال به *میکروفون* برنامه مقصد به درایور مجازی معتبر و انتخاب آن در آن برنامه نیاز دارد. در این نسخه ادعای انتقال کاملاً مستقل بین دو برنامه وجود ندارد.

## آزمایش‌های انجام‌شده

- تست‌های Go روی Linux با Race Detector برای انتخاب endpoint، Start/Stop، خطا، جلوگیری از Replay و تأیید محلی موفق بودند.
- تست DOM شبیه‌سازی‌شده JavaScript برای غیرفعال بودن انتقال در حالت پیش‌فرض، عدم آغاز خودکار و نمایش امن نام دستگاه‌ها موفق بود.
- کامپایل Windows amd64 Go و `go vet` با نسخه واقعی فایل `discovery_windows.go` موفق بود.
- **تست واقعی صدا روی ویندوز، تست درایور، کنترل latency/echo، نصب روی سیستم خام و تأیید Defender انجام نشده‌اند.** هیچ EXE یا MSI در GitHub Releases منتشر نمی‌شود.

## مراحل پیش از انتشار نسخه نصب‌شدنی

۱. تست زنده Windows x64: فعال بودن دستگاه‌ها، COM lifetime، فرمت‌های مختلف، تغییر دستگاه در حین انتقال، خروج و توقف اضطراری.

۲. اصلاح خطاهای نمونه‌برداری، نوسان ساعت/queue و ثبت وضعیت خرابی صوتی در UI.

۳. Application Loopback برای صدای اختصاصی برنامه و معماری ورودی مجازی معتبر، با بررسی مجوز انتشار درایور.

۴. ساخت Setup استاندارد ویندوز، بررسی امضا و Defender و آزمون نصب روی ویندوز خام.

**Magic Core: Deferred / Not Required.**
